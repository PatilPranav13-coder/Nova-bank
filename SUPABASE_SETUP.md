# NovaBank multi-user backend setup

NovaBank is a simulated banking project. It is not a real bank, wallet, payment service, or deposit-taking product.

## Included backend capabilities
- Individual accounts tied to Supabase Auth users.
- Unique account numbers generated by PostgreSQL.
- ₹1,000 simulated welcome credit per new account.
- Server-side atomic deposit, withdrawal, and account-to-account transfer functions.
- Per-user transaction history.
- Row Level Security so users can read only their own records; admins can read all records.
- No direct browser permission to edit balances or transaction rows.

## Setup
1. Create a project at https://supabase.com/dashboard.
2. Open SQL Editor in that project.
3. Open the supabase/schema.sql file in this repository, paste all its contents into SQL Editor, and run it.
4. In Authentication > Providers > Email, enable email/password sign-in.
5. For initial testing, email confirmation can be disabled. Before public launch, enable email confirmation and configure an email provider.
6. In Authentication > URL Configuration, set the Site URL to your GitHub Pages URL and add that URL plus /** as allowed redirect URLs.

## Admin access
After creating your own account through NovaBank, run this query in SQL Editor, replacing the email:

    update public.profiles p
    set is_admin = true
    from auth.users u
    where p.id = u.id and u.email = 'YOUR_EMAIL_ADDRESS';

Only grant admin access to your own trusted account. The admin flag cannot be changed by browser clients.

## Frontend connection
The frontend will need the Supabase Project URL and the browser-safe publishable key (or legacy anon key), found in Project Settings > API. Never expose the service-role key, secret key, or database password in frontend code or GitHub.

The current ATM interface still uses browser-local demo storage. The multi-user frontend integration is the next step after the Supabase project exists and its URL and publishable/anon key are available.
